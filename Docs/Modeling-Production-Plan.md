# WorldForge Modeling production plan

This plan implements WF-03 from the [WorldForge Master Blueprint](../Development%20Drive/WorldForge_Master_Blueprint_v3.md). The release target is a native polygon-modeling workspace that can create, revise, validate, and deliver static game assets from one project. Artists should be able to model a prop from a primitive, modify a Blender- or Maya-authored mesh, prepare UVs and material slots, and see the saved result in the World Editor and the Windows Player.

## Starting point

The current implementation includes parametric primitives, object and component selection tools, undoable transforms, connected soft selection, symmetry, snapping, core topology operations, multi-face Knife, axis Bisect, surface quad placement, a persistent modifier stack with Shrinkwrap, seam-based UV islands, named UV sets, evaluated GLB export, one reduced LOD and custom collider bounds. A Knife path can cross multiple faces or turn along multiple non-crossing segments on one original face. Edge bevel handles disjoint edges at closed three-face corners and a complete supported face perimeter. Shrinkwrap follows a target asset in mesh-local coordinates and rejects dependency cycles. Named UV sets retain their previous layout after a topology edit and indicate when they need rebuilding. Unwrap supports open charts with holes and requires seams across handles and closed surfaces. LOD uses a cell-size setting and exposes the resulting mesh for inspection.

Adjoining-edge bevel now handles closed junctions with convex planar faces. Mirror bisects crossing meshes and supports a chosen source side. Voxel Remesh reconstructs a closed sampled surface with a cancellable preview and approximates UVs and material assignments from the source. Boolean uses the Manifold solid geometry library for Difference, Union, and Intersection. Cutter offsets are in asset-local coordinates. UV pins persist per set. Unwrap keeps the existing outer boundary of a pinned island, and packing works around pinned islands. Topology edits preserve pins on faces that can be matched unambiguously. [Manifold C++ documentation](https://manifoldcad.org/docs/html/classmanifold_1_1_manifold.html)

The local release checks cover packaged-editor authoring, face, edge and vertex picking, and the heavier geometry tools. Clean Windows installation and hardware verification remain open. The current bevel and Boolean input limits are part of the supported workflow.

WorldForge already has a live Vulkan viewport with face picking, an asset registry with linked instances, static GLB import and reimport, single-face extrusion, perimeter bevel on constrained geometry, midpoint quad-loop cuts, a one-sided Mirror X modifier, and planar face UV editing. Mesh changes use the existing project undo stack, and asset references survive save and reopen. The current mesh stores vertex positions, polygon faces, corner UVs and normals, and material assignments. Edges are inferred from face boundaries, and the current viewport reports face indices. These are the integration points for the first milestone. [Editor features](../README.md) · [Mesh structures](../Engine/Geometry/Mesh.h) · [Project store](../State/ProjectStore.h)

The [Blender source review](Modeling-Source-Review.md) traces the viewport, BMesh, modifiers, UV tools, and operator lifecycle. Its early WorldForge status predates the current live implementation. For design, use Blender's mode-sensitive viewport and editable modifier stack, Maya's interactive cutting and welding, and Maya's practice of exposing precision controls where the active tool needs them. ### What makes modeling easier

- **Put the action under the pointer.** Hover highlights the component that a click will select. For loop cut, show the prospective loop and where it will stop. For weld, show the merge target and resulting vertex position. Show the bevel profile and its width limit before committing.
- **Give mouse and numeric input the same result.** Drag to preview, enter exact dimensions or an angle, constrain an axis, snap, then confirm or press Escape. A completed operation creates one undo entry. Cancellation leaves geometry, selection, linked instances and dirty state as they were at tool entry.
- **Keep feedback actionable.** Explain unavailable actions in the current mode. A bridge prompt can say to select two open borders. If a mesh has a non-manifold edge or overlapping UVs, selecting the diagnostic should frame and highlight the affected elements.
- **Reduce repeated work.** Repeat the last operation with its settings, duplicate as an independent asset or linked instance with explicit labels, and let the artist switch between base cage and evaluated result. Linked edits should identify the asset and show the affected instance count. Provide Make Unique when the artist wants to change one instance.
- **Keep expertise discoverable.** Command search, menus, shortcuts and context actions call the same command. Publish a default keymap with remapping and a future Blender- or Maya-style preset. Protect text-field focus and existing global save and undo shortcuts. Keyboard users must be able to activate and cancel each shipped tool and read its options and errors.

## Engineering decisions

1. **Keep asset identity, edit topology and runtime geometry distinct.** An asset ID survives edits, reimport and reopening. Keep polygon loops and corner attributes in the editable mesh, with explicit or cached edge adjacency for editing. Benchmark indexed adjacency before choosing whether a deeper half-edge rewrite is needed. Keep evaluated modifier meshes and render triangles derived from the authored mesh, with a mapping back to editable components where possible. Display the edit cage for generated geometry without an unambiguous mapping.
2. **Scope component selection to a mesh revision.** A command receives the target asset, expected revision, active domain, component handles, and typed parameters. Stable handles or explicit remaps cover edits within the supported topology session. A topology edit returns retained, created, merged and removed elements so the next action targets the right selection. Clear or rebuild stale selection on reopen or reimport when mapping is unavailable. Never trust a render triangle index as a source polygon handle.
3. **Use the existing project transaction path.** A preview works on temporary data. A commit validates topology and parameters, updates the asset and relevant selections, invalidates the affected derived data and pushes one undo transaction. For heavy operations, run from a revisioned snapshot and reject a result if the source changed while the operation was running. Existing asset saves and backups need migration fixtures before any schema change ships.
4. **Define attribute behavior per operator.** Preserve surviving material, UV, seam, normal and crease assignments. Define inheritance or interpolation for new elements, and document when regeneration is needed. Edge adjacency and selection rules must support an intentional open mesh such as a plane. Validate finite coordinates, legal indices and face loops universally. Apply manifold, watertightness and overlap checks according to the asset's purpose.
5. **Track dependencies by what changed.** A position-only edit may invalidate bounds, render buffers and collision. A topology change may also invalidate LODs, baked maps, or downstream rig and morph bindings. Surface stale dependent data and offer regeneration for supported targets. Preserve project references and avoid rebuilding unrelated assets. Check undo, redo and reimport through the same dependency path.
6. **Treat GLB as evaluated interchange.** Test units, up axis, negative scales, material primitives, UV splits and normal/tangent data. Store editable topology and modifier settings in the native project. Report import/export limits for textures, animation, skeletons, compression and other features until each path is implemented. Texture and Material consume slots and UVs through the project asset contract. [Khronos glTF 2.0 specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)

## Blender integration and Forge Intelligence

The proposed default is native C++ editing through the same command service used by menus and shortcuts. The Blender source remains a behavioral and architectural reference. Evaluate an optional external Blender worker separately for conversions or batch jobs that need Blender. The earlier local probe exercised scripted extrusion and a file round trip. Product integration, supported operations, failure handling and packaging are still open. Review the license and dependency closure before incorporating or distributing Blender code. [WorldForge Blender source review](Modeling-Source-Review.md) · [Blender source license notice](https://github.com/blender/blender/blob/main/COPYING)

Start Forge Intelligence with inspect, select, validate, and propose. A request such as “bevel the sharp outer edges by 2 mm” should resolve the target selection, show the proposed geometry and measurements, and let the artist adjust, apply or discard it. The accepted change uses the same typed operation, revision checks and undo as a manual edit. The workflow should report ambiguity, stale input, or an unsupported operation with a recoverable result. Manual tools work independently of the assistant. AI-assisted editing and the optional Blender worker can be evaluated alongside the native milestones.

## Production acceptance

The [Blender and Maya workflow comparison](Modeling-Source-Review.md#outliner-details-and-materials) covers the right-hand panels. The Modeling Outliner uses the same saved scene groups and visibility as World Editor. Details exposes material slots and map status on the selected asset. Keep transform parenting, hierarchy propagation, and shader graph authoring scoped to their respective scene and material systems.

Before moving on, run the two artist workflows and the import fixture in the packaged build, including the existing World Editor and Player paths. Record Vulkan validation and clean Windows Player results separately from local authoring test results. Handoff to Texture and Material includes a validated mesh with UV sets, material slots and a recorded revision. Sculpting and Rigging receive the same editable asset identity and can detect when a topology change affects their data.

The native authoring audit covers the equipment-case workflow from a sized cube through segmented bevel, inset, extrude, loop cut, UV unwrap, two material slots, Mirror and Array, shared edits, Make Unique, reopening, GLB round-trip, and playable export. Its exported scene runs in the packaged Player on the development PC. The fixture drives the geometry and project APIs. A separate walkthrough in the packaged editor exercised cube creation, viewport face selection, extrusion, undo and redo, sharp seams, UV unwrap, GLB export, and drawing a separate retopology patch. Both assets were present when the saved project reopened.

The retopology audit imports a curved GLB, draws a quad through the Vulkan viewport, extends its boundary, unwraps the strip, and checks the source asset after reopening. It also conforms and relaxes a separate patch while keeping its boundary fixed. The conform regression covers a camera framed inside the reference surface.

The GTX 1650 viewport benchmark uses 10,000, 100,000 and 1,000,000 triangle grids. At 100,000 triangles, p95 orbit, face pick, edge pick and vertex pick were 10.4, 7.8, 14.0 and 55.7 ms respectively through frame submission. The one-million-triangle stress case reached 352.5 ms p95 for vertex picks. The operation benchmark measured Boolean Difference at 43.6 ms, Decimate at 11.3 ms and Voxel Remesh at 1.58 s on an 80 × 64 sphere. The benchmark runs with `WorldForgeEditorAudit.exe <output-dir> <source-dir> --modeling-benchmark`.

For clean Windows verification, copy the complete verification package to a separate Windows installation with a Vulkan-capable graphics driver. If the VC++ runtime is missing, run the bundled `bin/vc_redist.x64.exe`. From PowerShell, run `& .\qa\Verify-PackagedWindows.ps1` at the package root. It records the OS, graphics adapters and binary hashes, checks that the Editor loads bundled Qt, and runs the equipment-case fixture in the Player with software and default rendering. Then open the packaged Editor and verify the Vulkan viewport by creating a blank project, adding a cube in Modeling, and saving and reopening it.

## First implementation ticket

Add **Object/Edit mode and vertex, edge and face selection with undoable transforms**. Exercise it on an existing project and a fresh cube with a second linked instance. Start with click and box selection, a clear visible-only/X-ray rule, and constrained move, rotate and scale. Use the existing save, selection and transaction paths and add the revision and selection mapping needed for this slice. Close the ticket when a viewport edit, Escape, undo/redo, save/reopen and shared-instance rendering all pass in the same fixture.
