# WorldForge Modeling source review

## Scope and current state

This review covers polygon modeling, its viewport and commands, modifiers, UV handoff, the boundary with other creation workspaces, and Blender automation. The source checkout was pinned to Blender 5.2.3 LTS, commit `e13b728c6880d3084d9d57c30031ed5df8b39dee`, matching the local application in the supplied screenshots. The review traced representative operations through the relevant subsystems and enumerated registered operators in eight namespaces. Exhaustive line review of Blender and execution of every registered operator are separate tasks. [Pinned Blender source](https://github.com/blender/blender/tree/e13b728c6880d3084d9d57c30031ed5df8b39dee)

WorldForge Modeling now uses a live Vulkan viewport with mesh component picking, topology edits, modifiers, UV editing, and PBR texture preview. The Model Outliner organizes mesh instances by their saved scene group. Details edits the selected instance's transforms and visibility, and the selected asset's materials, geometry, and modifiers. Linked instances share asset-level edits. [Modeling workspace](../Workspaces/ModelingWorkspace.cpp) · [Project store](../State/ProjectStore.cpp) · [Live viewport](../Components/LiveViewport.cpp)

## The Modeling interface

The first screenshot identifies the workspace strip. Every workspace tab is a direct destination with an icon, name, and selected state. Drop per-tab chevrons, preserve overflow scrolling when space is tight, and keep each workspace’s menus inside its editing area. Current Qt source already draws the tabs as icon plus text and switches the workspace on tab selection. The earlier concept image inherited the chevrons from the visual reference. [WorldForge tab drawing and wiring](../App/MainWindow.cpp)

The second screenshot shows how Blender makes more tools accessible without filling the viewport with command rows. Its header presents modes, selection domains, menus, and viewport toggles. Its left toolbar shows tools for the active mode and groups related variants behind a tool flyout. The right column stacks the Outliner over Properties. WorldForge can preserve this information hierarchy using its existing visual language.

| Area | WorldForge Modeling design |
|---|---|
| Workspace strip | Direct tabs including Modeling, Sculpting, UV Editing, Texture, Material, Rigging, and Animation. |
| Header | Object/Edit mode and vertex/edge/face selection in Edit mode. Expose View, Select, Add, Mesh, Vertex, Edge, Face, and UV by mode. Keep pivot, orientation, snapping, X-ray, overlays, and shading close to the view. |
| Left tool strip | Object mode shows select, cursor or pivot placement, and transforms. Edit mode adds compact groups for Extrude, Inset, Bevel, Loop Cut, Knife, Poly Build, Spin, Smooth, Slide, and Rip as they become functional. Group variations in flyouts. |
| Interaction | Search and context menus expose the same command registry as the tool strip and keyboard shortcuts. Numeric input, axis constraints, live preview, commit and cancel use the same operation. Support an optional Blender-style keymap and protect text-entry focus. |
| Right column | Outliner above Properties. Properties changes with the object, mode, and active tool. Give object transforms, mesh attributes, material slots, and the modifier stack dedicated sections. Show one editable tool settings surface and an optional Adjust Last Operation panel. |
| Canvas | Full-height editable mesh view by default. Assets and diagnostics open on demand. UV Editing uses a linked 2D/3D split with explicit selection-sync behavior. Sculpting uses a brush shelf. Animation uses a time editor under its preview. Those panels belong where the corresponding work happens. |

## How to use Blender

| Approach | Role |
|---|---|
| Independent native implementation | WorldForge owns interactive selection, viewport, authoring documents and commands, and the operations its engine can support. Use Blender’s public behavior and architecture as references. Keep the editable mesh, modifier results, and runtime buffers separate. |
| Optional external Blender worker | Prototype Forge Intelligence and advanced conversion through a pinned installed Blender executable and documented `bpy` / `bmesh` APIs. The worker accepts typed jobs, edits a project-scoped working copy, and returns validated artifacts and diagnostics. Keep a `.blend` source when it owns a procedural stack. Use GLB for evaluated interchange and report lost authoring details. |
| Direct C++ reuse or fork | Inspect each proposed file and its dependency closure. The sampled Blender UI, BMesh, edit operator, and Bevel sources carry GPL-2.0-or-later headers. BMesh internals, editor operators, RNA, dependency graph and window-manager services are integrated Blender subsystems. Decide the distribution and license model before incorporating GPL-covered code. Review any distributed adapter separately. [Blender licensing](https://www.blender.org/about/license/), [Blender source license notice](https://github.com/blender/blender/blob/v5.2.3/COPYING) |

For native authoring, define a versioned mesh asset with stable asset identity, revisioned element selection, explicit vertex/edge/face/corner attributes, and separate derived render data. Each typed edit carries an expected revision, selection IDs, validated parameters, and an undo record. Topology operators should return an element remap and explicit attribute/dependency changes. The Qt editor, command search, keyboard bindings and Forge Intelligence should call the same application service.

## Forge Intelligence modeling workflow

1. Inspect the selected asset, geometry revision, bounds, units, modifier stack, selection, material slots, and dependencies. For Blender jobs, check the installed version and which operations can run in the chosen context.
2. Produce a bounded plan of typed operations such as select faces by an explicit predicate, extrude by a measured distance, add a non-destructive bevel, unwrap, and validate. Resolve the predicate to a concrete selection against the current revision. Report ambiguity or a stale selection before editing.
3. Execute on a working copy. Use BMesh for data-level topology and Blender operators where their context and `poll()` support the job. Keep interactive Knife or other modal tools out of the headless registry until an explicit data-level operation is validated. Run with automatic scripts disabled when opening files, and use only trusted adapter code and project-scoped file access. [Blender API operator context](https://docs.blender.org/api/main/info_quickstart.html), [BMesh Python API](https://docs.blender.org/api/current/bmesh.html), [Blender script controls](https://docs.blender.org/manual/id/latest/advanced/scripting/security.html)
4. Present the before/after geometry and checks the artist would use: bounds, face and triangle counts, topology, material and UV continuity, and dependencies needing attention. Accept the candidate as one revisioned transaction or discard it. Record the input hash, version, operations, outputs and diagnostics for replay.

A local probe exercised the worker idea with Blender 5.2.3. A typed request targeted a cube by asset identity and expected revision, rejected a stale edit, extruded its top face by 0.35 m and verified a manifold result. The base mesh changed from 8 vertices, 12 edges and 6 faces to 12 vertices, 20 edges and 10 faces. A separate Bevel modifier produced 66 evaluated faces. The edited `.blend` reopened with the base edit and modifier intact, and the source file reopened at its original revision. This verifies a small scripted Blender operation and file round trip. WorldForge integration, interactive undo, broader command coverage and an AI model evaluation remain open.

## First implementation sequence

1. Complete First Light’s live viewport, selection, typed scene commands, and save/reopen. Add the asset registry and original Blender GLB import with tested unit and coordinate conversion.
2. Build the native Modeling layout and mesh document together. Connect viewport picking, Outliner selection, Edit mode, command menus, and the tool strip to real commands. Use a simple original prop fixture.
3. Close the vertical slice with face extrusion, undo/redo, save/reopen, and an existing World instance updating under the same asset ID. Then add Inset, Bevel, Loop Cut, Mirror, and basic UV Editing with shared fixtures.
4. Build the optional Blender worker as an independent prototype around the tested operation. Compare native and Blender results on common fixtures by geometry and attribute invariants. Expand the parity register with explicit unsupported cases and dependency tests before reusing the pattern in the other studios.
